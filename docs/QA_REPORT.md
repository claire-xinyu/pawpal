# V3.2 验收

## 可重复运行

`npm test`：20项模型检查 + 84项用户场景检查 + 40项状态/布局检查。`npm run test:privacy`检查私有文件不入库、公开图片无原始元数据。Chrome使用独立临时浏览器，不读个人账号或图库。

## 五条场景

1. 首页耳朵进食摘要 → 耳朵健康页 → 7/30/90天趋势 → 点击数据点/选择日期。
2. 猫砂盆事件 → 使用时长和体重详情 → 归属从耳朵改尾巴并备注 → 双方统计更新 → 刷新仍保留。
3. 成长 → 耳朵 → 2024年 → 对应照片 → 前后翻看。月份、描述/标签搜索以及往年同月、初到家时均使用已有日期。
4. 尾巴 → 上传 → 独立拍摄日期 → IndexedDB刷新 → 编辑描述 → 文字查找。
5. 照片详情 → 分享 → 明确仅浏览器体验、非公开发布 → 确认 → 广场显示，旧收藏/物种筛选不隐藏新内容。

另验证新用户空间没有设备模拟和案例医疗记录，单次称重不绘曲线；体重单位、疫苗驱虫、提醒、观察、照护时间线、社区反馈、删除取消/确认及模式隔离。

## 错误与边界

不可读图片、IndexedDB禁用、LocalStorage配额、无宠物、损坏数据备份、未知体重日期、封面刷新、漂流瓶刷新反馈。失败保留输入，不只显示Toast伪造成功。

## 视觉复核

390/768/1440px，四页和社区栏目。对比改造前后截图后修正：桌面单宠照片占半宽、稀疏月份形成空白、默认设备事件过长、漂流瓶首图加载时机。相册默认按年份组织，选择月份后按月浏览。

截图脚本主动等待图片解码再取图。测试图片解码时显式启用加载，避免屏外懒加载被误认为资源失败。无横向溢出；包含键盘数据点操作和移动端日期选择。

## 发布

匿名GitHub Pages访问、相同URL、页面和生产模块与本地文件一致，随后线上执行同样84项场景检查。实际结果写入本聊天交付报告，不把尚未运行的验收写成成功。
